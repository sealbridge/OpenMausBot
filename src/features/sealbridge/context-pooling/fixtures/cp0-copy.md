## 0. どの画面にも出す限界の一文（必須）

相手の端末やモデルが、一度見た内容を残すことを、こちらの仕組みだけでは止められません。渡す範囲は小さく、期限は短くしてください。

（長い版・ヘルプ用）一度復号して相手のエージェントが読んだ平文は、コピーや別の場所への保存を、暗号や作業フォルダの設定だけでは証明つきで防げません。Sealbridge ができるのは、切り出し・送り方・期限・監査の記録と、画面での注意です。

## 1. 送るとき — 送り方の選択

**見出し:** 送り方

**リード:** 相手に渡す切り出しの扱い方です。送ったあと、この設定の記録自体は書き換えられません（相手の実際の振る舞いまで保証するものではありません）。

| 内部名 | 選択肢のラベル | 1行の説明（選択肢の下） |
| --- | --- | --- |
| `view_only` | 閲覧のみ | ほかの人には頼み直せません（仕組みで止まります）。残さないよう依頼しますが、相手側で本当に残らないかは確認できません。 |
| `approval_redelegation` | 承認してほかへ頼む | 相手が、さらに別の相手へ頼むときは、その所有者の承認と、より狭い範囲が必要です。段は1つまで。その先の相手の身元はあなたに見えます。 |
| `hand_over` | 引き渡し（納品は残してよい） | ほかの人には頼み直せません。検収した納品物は相手が手元に残してよいです。渡した切り出し（入力）は、既定では「残してよい」という許可を出していません。 |

**既定:** 「閲覧のみ」を最初から選んだ状態にする。

**「承認してほかへ頼む」を選んだ直後の追加文:**
最大1段です。段ごとに相手の所有者の承認が要ります。2段目の相手のDID（身元）は、結果の画面であなたに見えます。あなたの身元は、既定では2段目には伝えません。

**「引き渡し」を選んだ直後の追加文:**
残してよいのは、検収が終わった納品物だけです。入力として渡した切り出しを残す場合は、下のスイッチを明示的にオンにしてください（既定はオフ）。

**入力を残すスイッチ（引き渡しのときだけ）**
- ラベル: 入力の切り出しも相手が残してよい
- 既定: オフ
- オンにしたときの一文: 切り出しそのものが相手の手元に残ります。本当に必要か確かめてください。

**送る前の共通注意（§0 の短い版を再掲）:**
相手の端末やモデルが、一度見た内容を残すことを、こちらの仕組みだけでは止められません。

**期限・大きさ（送る画面の欄の近く）**
- 期限のラベル: 有効期限
- 既定表示: 24時間（最大7日まで延ばせます）
- 上限超過時: 有効期限は7日以内にしてください
- 大きさのラベル: 切り出しの大きさ
- 目安表示: ○○ KB / 上限 64 KB
- 超過時: 切り出しが 64 KB を超えています。列や行を減らしてください

**観点（angle）のプレースホルダ:** この範囲だけ見て、次の観点で返してください（例: 工程の可否だけ／材料費の内訳見積もり）

**送るボタン横の要約1行（例）:** 送り方: 閲覧のみ · 期限 24時間 · 12 KB

## 2. 受け取り — 受信箱のバッジ

依頼の行の左（または題名の横）にバッジを1つ。

| 送り方 | バッジ短文 | タップ／ホバーの補足 |
| --- | --- | --- |
| 閲覧のみ | 閲覧のみ | ほかへ頼み直せません（仕組みで止まります）。送り手は残さないよう依頼していますが、実際に残るかどうかは確認できません。 |
| 承認してほかへ頼む | ほかへ可（1段・要承認） | あなたが承認し、範囲を狭めたときだけ、さらに1先へ頼めます。あなたのDIDは元の依頼主に見えます。一度見た内容の残存は止められません。 |
| 引き渡し | 引き渡し（納品は保持可） | 検収した納品物は残してよいです。入力の切り出しは、送り手が許したときだけ残せます。一度見た内容の残存は止められません。 |

**grant 要約（検査結果の横・中身は出さない）**
- 観点: （短文）
- 範囲: 列 ○件 · 拒否列 ○件（詳細は開く前はダイジェストのみ）
- 期限: 残り ○時間
- 大きさ: ○○ KB
- 保持: 残さない / 納品のみ可 / 入力も可

**開く前の確認（共通）:**
開くと、切り出しがこの端末のエージェントに渡ります。§0 の限界の一文を再掲する。

## 3. 再委任の承認カード（「承認してほかへ頼む」のときだけ）

**題名:** ほかの相手へ、狭めて頼む

**本文の順序（上から）:**
1. 元の観点: …
2. 頼む先: （表示名）· DID の短縮
3. 狭める前 → 狭めた後: 差分の要約（落ちた列・減った行を箇条書き）
4. この先の深さ: 残り 0（これ以上ほかへ頼めません）
5. 元の依頼主への見え方: 頼む先のDIDは、元の依頼主に見えます
6. あなたの身元: 既定では頼む先に伝えません（ダイジェストのみ）。伝える場合は次をオン
   - スイッチ: 元の依頼主の身元を先の相手に伝える（既定オフ）
7. §0 の限界の一文（**長い版**を出す。2段目が絡むため）

**ボタン:**
- 主: 承認して送る
- 副: 断る
- （任意）戻って範囲を直す

**準備中（CP5a 前）の代わり文:**
「承認してほかへ頼む」は、委任の連鎖（DelegationLink）が入るまで使えません。いまは閲覧のみか引き渡しを選んでください。

## 4. 保持の宣言文（契約・画面の固定句）

送り方に応じて、送る側・受ける側の両方に同じ文を出す。

**閲覧のみ**
削除の扱い: 作業が終わったら、渡された切り出しを作業フォルダから消す扱いです。相手側で本当に消えたかは確認・証明できません。

**承認してほかへ頼む**
削除の扱い（推奨）: 各段とも、作業が終わったら切り出しを消す扱いです。先の段へ渡すのは、承認と狭めのあとの切り出しだけです。実際に残っていないかの証明はできません。

**引き渡し（入力オフ）**
納品物の保持: 検収が終わった納品物は、受け手が手元に残してよいです。入力の切り出しは、残す許可を出していません（実際に残っていないかの証明はできません）。

**引き渡し（入力オン）**
納品物と入力の保持: 検収が終わった納品物と、渡された切り出しの両方を、受け手が手元に残してよいと送り手が明示しました。

| 状況 | 文面 |
| --- | --- |
| 期限が近い（残り3時間未満） | この切り出しの期限まで残り ○時間です |

| リレー上限に近い注意（任意） | 封筒の上限（256 KB）に近づいています。これ以上足さないでください |

## 6. 監査ビューに出す行（中身は載せない）

各行は日時 · 種別 · ダイジェスト短縮 · 判定。

| 種別（表示名） | いつ |
| --- | --- |
| 持ち寄りを送った | 送る承認のあと |
| 送り方 | 閲覧のみ / 承認してほかへ頼む / 引き渡し |
| 受信箱で開いた | 所有者が開く |
| 捨てた | 所有者が捨てる |
| 削除を試みた | 作業フォルダ削除を走らせたとき（実装後） |
| ほかへ頼むのを承認した | 再委任カードで承認 |
| ほかへ頼むのを断った | 再委任カードで拒否 |
| 狭めたあとの範囲 | 子の切り出しダイジェストだけ |
| 検収した | VERIFY_ACCEPT 相当 |
| 限界の注意を示した | 送る・開く・再委任の各画面で一文を出した記録（任意・推奨） |

監査の画面フッター: 中身の文章は監査に残していません。ダイジェストと判断だけです。

## 8. Claude Code の批判と反映

`claude -p` を1回実行した（Read のみ）。

**重大として直したこと**
1. 「残さない約束」が保証に読める → 「残さないよう依頼／削除の扱い」＋確認できない旨に差し替え。再委任不可（仕組みで止まる）と非保持（確認できない）の強さを分けた。
2. 引き渡しの「既定では残しません」→ 「残してよいという許可を出していません」。
3. バッジ3種すべてに残存を止められない旨を入れた。再委任カードは限界の一文の長い版を指定。

**中くらい**
- 送り方リードの「勝手には変わりません」を、設定記録が変わらない意味に限定。
- 引き渡しラベルに「納品は残してよい」を足した。
